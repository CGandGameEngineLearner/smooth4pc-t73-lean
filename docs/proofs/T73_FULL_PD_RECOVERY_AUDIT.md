# Exhaustive recovery audit for the reduced handle diagram

Date: 2026-09-05

## Result

The workspace does not determine a standard seven-component Kirby PD code.
No full exporter can be produced without choosing new geometry.

The installed topology tools were checked with
`/tmp/t73-topology-tools/bin/python`: Regina 7.4.1, SnapPy 3.3.2,
and Spherogram 2.4.1 import successfully. The obstruction occurs before any
recognition engine can be called.

The deterministic negative adapter result is saved in
`audit/t73_pd_spherogram_adapter_report.json`; it can be regenerated and
byte-compared with `python3 scripts/audit_t73_pd_spherogram_adapter.py
--write` and `--check`.

## Recoverable prefixes

Several useful but different objects are present.

1. `geometry/t73_actual_ar_link.json` contains pre-cancellation AR
   cores and framing pieces in mapping-torus charts.
2. The cancellation files contain band records and event ownership, but no
   single final ambient polyline for all five surviving components.
3. `audit/t73_reduced_link_pd.json` contains 1958 signed
   mixed-component crossing records generated by a railroad projection.
4. `geometry/t73_selected_source_exterior.json` contains four
   *cabled coefficient* cycles with complete endpoint successor order, 630
   rational exterior intervals, and framing push-offs. This recovers the
   selected coefficient source incidence, not the five-component reduced
   attaching link.

The fourth object corrects the coefficient exterior to four insertion spheres
with endpoint counts \((88,88,542,542)\). It cannot be substituted for a
closed Kirby link because its 1260 endpoints are meant for arbitrary
insertion tangles.

## Irrecoverable fields and exact conflicts

### Along-segment crossing order

The reduced ledger gives `over_segment`/`under_segment`, but
390 railroad segments contain multiple crossings. For example segment
`m_2:0` occurs at crossing records 10, 74, 702, 766, and 1396. The
file stores no projection parameter ordering these five points. Swapping
records 10 and 74 along that segment preserves every existing ledger field
and every selected signed linking sum, but changes the half-edge successor
cycle of the resulting PD code.

The source generator can recreate one *chosen railroad convention* because
its private connector formulas contain parameters. That does not bind the
choice to the actual post-cancellation AR link, and the generated artifact
discarded the parameters.

### Self-crossings and local knots

The builder loops only over pairs of distinct component names. It never
computes self-crossings. Tying a local trefoil into a connector of \(m_2\)
inside a ball disjoint from all other components leaves its free handle word,
all mixed crossings, and all pairwise linking sums unchanged. It changes the
knot type and standard PD code. Thus self-crossing data are not uniquely
recoverable.

### The \(r_{zx}\) component

The post-cancellation free word of \(r_{zx}\) is empty and its ledger
incidence is zero. An unknot and any local knot inside the zero-handle both
have empty handle word and can be arranged to have no mixed crossings.
They produce identical current records but different components. The
pre-cancellation dual-cell polyline does not determine its image without a
complete ambient cancellation map.

### Dotted handle components

A Spherogram link is a link in \(S^3\), whereas the five attaching components
are described in a genus-two 1-handlebody boundary. Conversion to a Kirby
diagram requires the dotted \(y,z\) circles, their embedding, and all
incidences with the attaching link, or an explicit triangulated handlebody
complement. None is stored in the reduced PD.

### Integer framings

The entries for \(m_2,m_3\) say only `same-product-framing`.
Spherogram/SnapPy Dehn filling requires a peripheral slope or integer diagram
framing. Without a common core and push-off in the final projection, the
linking number \(\operatorname{lk}(K,K')\) and its blackboard correction
cannot be derived. A local curl changes blackboard writhe while leaving the
current product-framing string unchanged.

## Minimal new input

`audit/t73_full_handle_diagram_input_contract.json` records the
minimal sufficient replacement: seven closed rational core polylines
(including \(r_{zx}\) and the dotted circles), five disjoint framing
push-offs for the 2-handle components, and one generic projection in a common ambient chart. From those
coordinates a fail-closed exporter can compute every mixed and self crossing,
the parameter order along every segment, half-edge successors, standard PD
rows, linking matrix, and integer framings.

Anything weaker requires a geometric choice not determined by the current
repository. In particular, adding only a standard PD code would permit
Spherogram conversion but would not prove that the diagram is the transported
AR handle presentation.

## Pivotal currying of the eight \(r_{xy}\) intervals

The eight \(r_{xy}\) coefficient intervals form four same-variance and four
opposite-variance Y/Z matchings. Standard rigid pivotal duality can bend an
endpoint and turn these into consistently typed source/target morphisms.
This is a canopolis/pivotal currying operation, not an ambient isotopy fixed
on the four insertion spheres.

In the normalized MWW tangle categories the pivotal identifications are
degree-zero equivalences. The separate selected cup
\(P_{86}\to P_{88}\) remains a noninvertible external tangle. Currying can
therefore repair variance/orientation typing and explain a single
\(P_{86}\to P_{88}\) presentation once the z coend and external cup are
specified, but it cannot supply the missing \(+271\) needed to turn the
two-representable degree 223 into 494. Eight degree-zero pivotal bends do not
alter the intrinsic shift calculation.
